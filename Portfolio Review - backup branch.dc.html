What I would change

Ordered by how much each one costs a visitor.

01

The emphasis colour is black

Every highlighted term uses .purple, which resolves to --imp-text-color: #050505 with !important. Card titles that set color:"purple" inline are overridden too. The hierarchy the markup describes never reaches the screen. Pick one real accent and let the class mean it.

1 line
02

White text on light grey fails contrast

Every inner page sits on --section-background-color (rgb 137→182) with color: white !important — roughly 2.1:1, against a 4.5:1 requirement. Publication cards make it worse by putting white venue names next to black titles inside the same sentence. Either darken the section or make the ink dark.

2 vars
03

The homepage has no hero

Home.js imports me2.png, word.png and the Type typewriter, then renders an empty container — so the first screen is a blank grey band and the page opens mid-biography. The styling for a hero already exists (.heading, .Typewriter__wrapper, .wave); nothing uses it. Also drop z-index:-1 on .home-section — it pushes the hero behind the page background.

1 file
04

Long pages are undifferentiated card walls

Courses runs 13 identical cards, Publications 12, News 5 — all the same box, no dates, no venue grouping, no sort. For an academic site the list itself is the content, so it should read as a list: year on the left, title, venue, then one link. Cards add a border and a shadow and remove scannability.

design
05

Typography has no system

Raleway loads for the body, then Georgia is re-declared per component and per inline style, with heading sizes set ad hoc (2.6em, 2.3em, 2.5em) in JSX. Meanwhile .home-about-body indents by padding-left:10vh, so the text inset changes when you resize the window vertically. Three sizes, one pairing, defined once.

CSS
06

Publication metadata needs a pass

Five different papers link to the same DOI (ieeexplore/9750136); the DAC entry is titled "2023 61st" but dated 2024; "Ashsish" appears five times; and the two Google Scholar links point at different user IDs (QxhKiig… on Home, pV4Hl-o… on Publications). This is the page reviewers actually read.

content
07

Small breakages worth clearing

The footer mail link is href="drprofmjha@gmail.com" with no mailto:, so it navigates to a relative path; one of its four columns is empty commented-out markup. Navbar.js attaches a scroll listener in the render body, adding one on every render and never removing it. ResumeNew.js mounts the same PDF three times as three separate documents at 1.7× with no loading state. Routes mix cases (/Publications, /Skills, /project), and "Courses" in the nav points to /about.

4 files
08

Eight nav items, no priority

Home, Publications, Experiences, Skills, Projects, Courses, Blogs & Lectures, CV all carry equal weight and collapse to a burger below 768px. For a research site, Publications, Experience and CV are the destinations; Courses, Skills and Blogs can live one level down. There is also no active-page state — defaultActiveKey="#home" never updates.
